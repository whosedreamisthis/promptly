# Feature History

- **Clerk Authentication:** Installed `@clerk/nextjs` and added `proxy.ts` with Clerk middleware (no protected routes yet). Added Sign in and Register buttons to the nav bar (`components/layout/NavBar.tsx`) that open modal sign-in/sign-up and also link to the `app/(auth)/sign-in` and `app/(auth)/register` pages. Supports Google and email/password, with links to switch between sign-in and sign-up. `.env.example` documents `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` and `CLERK_SECRET_KEY`.

- **Sidebar:** Added a full-height sidebar (`components/sidebar/`: `Sidebar`, `AppShell`, `SidebarSection`, `SidebarItem`, `ItemMenu`, `SettingsModal`) with a new `Logo`. It has a header with logo, "Promptly" title and an X close button, a search box, New chat, collapsible Notebooks and Recents sections with a scroll divider, and a footer with avatar, name, "Free Tier" and a settings modal. Rows have a ⋮ menu: chats get share, pin, rename, add to notebook and delete; notebooks get pin, rename and delete. The sidebar closes fully when an option is clicked and reopens from a hamburger icon with the title beside it; below 768px it is a drawer with a backdrop. The top navbar only shows when signed out. Also applied the pastel palette (gradient background, glass navbar, lavender scrollbars). Data is mock, in `lib/mock-chats.ts`. Added `lucide-react`.

- **Sidebar Footer Clerk Account Button:** Removed the "Free Tier" text from the sidebar footer and replaced the custom avatar and name with Clerk's `UserButton` (`showName`, avatar left of the name, styled with the pastel palette), so clicking it opens Manage account and Sign out; signed-out users still see a Guest fallback and the settings gear stays on the right with a pointer cursor. Also removed the logo beside the hamburger icon when the sidebar is closed (title only), added `app/icon.svg` as the Promptly favicon in place of `favicon.ico`, and set the page title to "Promptly". Key files: `components/sidebar/Sidebar.tsx`, `components/sidebar/AppShell.tsx`, `app/icon.svg`, `app/layout.tsx`.

- **New Chat View:** Added the home screen (`app/page.tsx` renders `components/chat/ChatView.tsx`) with a centered Promptly logo and a greeting using the signed-in user's first name (generic fallback when signed out). The floating input bar (`ChatInput.tsx`) has a `+` file button with drag-and-drop (png, jpg, webp, pdf, txt, csv, docx; removable chips, `lib/chat-files.ts`), an auto-resizing text area (max 128px, "Ask Promptly", Enter sends, Shift+Enter adds a line), a microphone for Web Speech dictation (`lib/use-speech-recognition.ts`, pulsing red ring, hidden where unsupported, cancelled when a message is sent) and a Send button shown once there is text or a file. Sending adds the message to a thread (`ChatThread.tsx`) and streams a mock reply word by word while the input is disabled. The sidebar New chat button resets the view; the bar has side padding to clear the bottom-left avatar and uses `env(safe-area-inset-bottom)` with `viewportFit: "cover"` in `app/layout.tsx`. A sparkle hero icon was tried and replaced with the Promptly logo to avoid resembling Gemini.

- **Chat Pages:** Chats now live at `app/chats/[chatId]/page.tsx` (params awaited inside Suspense, as required by Cache Components). Chat list, messages and the mock streamed reply moved into `components/chat/ChatsProvider.tsx` so state survives navigation. On `/`, `ChatView` generates a draft chat id in the background and, on the first message, saves the chat under it (title from the first message) and navigates to `/chats/[id]`. The sidebar New chat button creates an empty "New chat" (reusing an untouched one) and opens its page; its first message renames it. `components/sidebar/RoutedSidebar.tsx` wires the sidebar to routing inside Suspense, highlights the open chat, and deleting the open chat returns to `/`. Chats are in memory only, so a refresh on a chat page shows an empty chat until persistence exists.

- **shadcn/ui Migration:** Initialized shadcn/ui (radix base, Tailwind v4, `components.json`, `components/ui/`, `cn` from `lib/utils.ts` using clsx and tailwind-merge) and mapped the pastel palette onto its theme variables in `app/globals.css` (mint primary, lavender secondary, vanilla border, 0.5rem radius). Replaced the hand-built `ItemMenu` with `DropdownMenu` (pin, rename, delete, share, and an "Add to notebook" sub-menu), `SettingsModal` with `Dialog`, `SidebarSection` with `Collapsible`, all buttons with `Button` (rounded-md, pointer cursor, lavender ghost hover), the sidebar search and chat bar with `InputGroup`, rename with `Input`, the chat text area with `Textarea` and attachment chips with `Badge`. The sidebar now also closes when the page area is clicked on desktop, and section headings only highlight on hover. Documented the shadcn-first rule in `context/ai-interaction.md` and `context/coding-standards.md`. Known quirk: the shadcn CLI generates imports from an unrelated `cn` package, which must be changed to `@/lib/utils`. Tooltip and ScrollArea were not adopted.

- **Database Persistence:** Replaced the mock chat data with Neon Postgres accessed through Prisma 7 (`prisma-client` generator in `app/generated/prisma`, `PrismaPg` adapter in `lib/db.ts`). `prisma/schema.prisma` defines `User` (id is the Clerk user id, created lazily by `ensureUser()` in `lib/session.ts`), `Notebook`, `Chat` (optional `notebookId`, `title` default "New Chat", `isCustomTitle`, `pinned`), `Message` (USER/ASSISTANT) and `Attachment` (metadata only), with cascade deletes from the user and set-null from notebook to chat. The first migration `init` was created with `prisma migrate dev`; `prisma.config.ts` uses `DATABASE_URL_UNPOOLED` for migrations and the app uses the pooled `DATABASE_URL`. Server actions in `actions/chats.ts` and `actions/notebooks.ts` run through `runAction` (`lib/run-action.ts`), which checks the Clerk session, validates with Zod (`lib/validations/chats.ts`), wraps errors and returns `{ success, data, error }`; all queries are scoped by `userId`, a manual rename sets `isCustomTitle`, `autoTitleChat` skips custom titles, and deleting a notebook keeps its chats. `ChatsLoader` (inside Suspense, required by Cache Components) loads the user's chats and notebooks into `ChatsProvider`, which now also owns notebook state and applies changes optimistically with a sonner toast and rollback on failure. `/chats/[chatId]` returns not-found for unknown or foreign chats, and a chat is only saved when created or first used. Removed `lib/mock-chats.ts`; added Vitest (`vitest.config.ts`, `npm test`) with 17 tests for the chat and notebook actions. Messages are not saved yet (replies are still placeholders); the Gemini integration will persist them. Notes: the Prisma CLI is pinned to 7.10.0 because npm resolved a prerelease 8.0 CLI without `migrate`; the `src/` prefix was dropped from project docs; the Neon project and branch ids are recorded in `CLAUDE.md`.

- **Notebook Pages:** Selecting or creating a notebook now navigates to `app/notebooks/[notebookId]/page.tsx` (params awaited inside Suspense) instead of tracking the active notebook in sidebar state; `RoutedSidebar` derives the active notebook from the URL, passes `activeNotebookId` and `onSelectNotebook` to `Sidebar`, and deleting the open notebook returns to `/`. `components/notebook/NotebookView.tsx` reads from `ChatsProvider` rather than the database so a notebook that is still being saved does not 404 (unknown ids show "Notebook not found"). It shows the notebook icon and title on one line, a "Past chats" list whose rows link to the chat and have a menu (rename inline via a small `RenameField`, pin, remove from notebook, delete), and the chat input, which creates a new chat, moves it into the notebook and opens it. Chats inside a notebook show a shadcn `Breadcrumb` (notebook > chat, both truncated) in `ChatView` that links back to the notebook. Added `components/ui/breadcrumb.tsx` via the shadcn CLI, fixing its `cn` import to `@/lib/utils`. Not done: per-chat dates in the list, because chat data on the client has no `updatedAt`.

- **Database Error Handling:** `getChatsData` in `lib/chats-data.ts` now retries up to 3 attempts (1.5s then 3s backoff) only on Prisma `P1001` (database unreachable), which covers Neon waking from scale-to-zero; other errors fail immediately. Because `ChatsLoader` lives in the root layout, a regular `error.tsx` cannot catch its failures, so `app/global-error.tsx` renders a full page with the Promptly logo and title header, a message explaining that the serverless Postgres may be waking up, and a Try again button, styled with the pastel theme and Geist. It only appears in production builds (`next dev` shows the error overlay); tested by running `next start` with an unreachable `DATABASE_URL`.

- **Message Persistence:** Added `addMessage` in `actions/messages.ts`, run through `runAction` (Clerk session, Zod validation from `lib/validations/messages.ts`, `{ success, data, error }` result). It checks the chat belongs to the user, creates the `Message` row with the client-generated id and role (USER/ASSISTANT), and bumps the chat's `updatedAt`. `ChatsProvider` saves the user message when it is sent and the placeholder assistant reply when streaming finishes; a failed save shows a toast. `/chats/[chatId]` now passes the chat's saved messages to `ChatView` as `initialMessages`, which shows them until the chat has messages in memory and seeds them into the provider through `seedMessages` (in-memory messages are never overwritten). Messages are limited to 10,000 characters (`MAX_MESSAGE_LENGTH`): the schema rejects empty and longer text, and `ChatInput` sets `maxLength` and truncates dictation. Added 5 Vitest tests in `actions/messages.test.ts`. Not done: attachments are not stored, so file names and file-only messages are not restored on reload, and chats created before this feature stay empty because nothing was saved for them.

- **Database Seed:** Added `prisma/seed.ts` and `prisma/seed-data.ts`, run with `npm run db:seed` (`prisma db seed` through `migrations.seed` in `prisma.config.ts`, using the new `tsx` dev dependency). It seeds 5 notebooks, 20 chats (6 in notebooks, 14 standalone) and 82 messages for the Clerk user in `seed-spec.md`, including the 18-message `chat_103` long thread and the empty notebook `nb_5`. Chats get their listed `updatedAt`, `isCustomTitle: true` and fixed ids; message `createdAt` values count up one minute apart so ordering is stable, and every message is validated against the 10,000 character schema. Re-runs are idempotent: one transaction upserts the user, deletes only that user's chats and notebooks, and recreates them. The script prints the database host and aborts unless `NODE_ENV` is not production and the host equals `SEED_ALLOWED_HOST` (documented in `.env.example`). The client is built like `lib/db.ts` with relative imports. Added 4 Vitest tests in `prisma/seed-data.test.ts`. The spec was rewritten to match the schema: `User` has only `id` and `Notebook` has no description. Not done: attachments are not seeded.

- **AI Integration:** Added `POST /api/chat` (`app/api/chat/route.ts`, `maxDuration` 60), which validates the body with `chatRequestSchema`, checks the Clerk session and chat ownership, saves the user message, loads the last 30 messages and streams a reply with `streamText` from AI SDK 7 (`ai`, `@ai-sdk/google`, model `gemini-3.8-flash` because `gemini-2.5-flash` is no longer available to new users, 2,000 output tokens, system prompt asking for three paragraphs or fewer, `GEMINI_API_KEY` passed explicitly). The assistant message is saved when streaming ends and its id is returned in the `X-Message-Id` header; aborting the request stops generation. `ChatsProvider` replaced the mock interval with a per-chat `AbortController`, reads the stream, toasts errors and removes the empty reply, and no longer saves messages itself (`actions/messages.ts` and its tests were deleted); file-only submissions show a toast because the route needs text. `generateChatTitle` in `actions/chats.ts` names a chat after its first exchange (3 to 5 words, cleaned by `cleanTitle`) only while `isCustomTitle` is false and returns the title for client state, keeping the first-message title on any failure. Assistant messages render as markdown through `ChatMarkdown` (`react-markdown`, `remark-gfm`, light code blocks, no syntax colours) and show a `ThinkingIndicator` while waiting. `USE_AI_MODEL=false` makes the route stream a canned markdown reply (`MOCK_REPLY`) and skips title generation to save tokens; the value is documented in `.env.example`. Added Vitest tests for the title action, `lib/ai.ts` and the request schema (38 tests total), and a Commands rule in `context/ai-interaction.md`. Not done: attachments are not sent to the model, there is no syntax highlighting, and `GEMINI_API_KEY` must be added on Vercel.

- **Code Scan and UI Review Fixes:** Fixed the findings of the code-scanner and ui-reviewer runs. `/api/chat` and `generateChatTitle` are limited to 20 calls per minute per user by an in-memory sliding window (`lib/rate-limit.ts`, per server instance), titles are only generated after the first exchange, oversized bodies return 413 and duplicate message ids 409. The route now saves the user message and its reply in one transaction with explicit `createdAt` values, so failed or aborted replies leave no dangling user message. `ensureUser` reads before it writes; chat and notebook lists are capped at 100 and loaded messages at 200 (`LIST_LIMIT`, `MESSAGE_LIMIT` in `lib/chats-data.ts`); create actions catch the unique-id error (`lib/db-errors.ts`) instead of find-then-create; pinning uses `setChatPinned` and `setNotebookPinned` with an explicit value. `ChatsProvider` is split into `useChatMessages` and `useNotebooks`, and its context into `useChats` (stable actions, chats, notebooks) and `useMessages` (messages, streaming), with chunk rendering limited to once per frame and memoised message rows, so streaming no longer re-renders the sidebar. `Sidebar` now reads chat state itself (10 props instead of 18) and is split into `SidebarHeader`, `SidebarFooter` and `useSidebarMenus`; `InlineRenameInput` and `ActionsMenu` replace the duplicated rename and menu code in the sidebar and notebook pages. Sidebar colours use theme tokens, new `--color-pastel-blush` and `--shadow-soft` tokens were added, buttons use `rounded-md`, and component types moved to `types/chats.ts`. UI fixes: palette colour and reduced-motion pulse for the dictation button, 40px icon buttons below `md`, shadcn tooltips (`components/ui/tooltip.tsx`, `cn` import fixed), a persistent `aria-live` status region, truncating file badges, scrollable message bubbles, lazy-loaded markdown with links opening in a new tab. The share item became "Copy link" and copies `/chats/{id}`; signed-out users are redirected from chat pages to `/sign-in`; the mock reply text and a redundant history slice were corrected. Added tests for the limiter, the error-code helper, the pin setters, create races and the first-exchange title rule (51 tests total). Not done or deliberately kept: `addMessageSchema` stays because the seed script uses it; the rate limit is not global across instances; lists are capped rather than paginated with a "load more"; mock mode still fails open when `USE_AI_MODEL` is missing; the UI reviewer had no browser, so responsive layouts at 375, 768 and 1280px were not checked.

- **Guest Chat:** Signed-out users can now chat on `/` without anything being saved. `POST /api/chat` no longer returns 401 when `ensureUser()` finds no session; it calls `guestReply`, which skips every database read and write and streams a reply (or the mock reply) with a fresh `X-Message-Id`. Because nothing is stored for guests, the client sends up to 29 earlier turns as an optional `history` array (`MAX_GUEST_HISTORY` and the extended `chatRequestSchema` in `lib/validations/messages.ts`, role USER/ASSISTANT, 10,000 characters each), and the body cap rose from 50 KB to 400 KB to fit it. Guests share the 20 per minute limit, keyed by the first `x-forwarded-for` address. `ChatsLoader` passes `isGuest` to `ChatsProvider`, which keeps one in-memory `guestChatId`: `sendMessage` adds the message and streams the reply under that id without creating a chat, titling it or navigating, and New chat clears the conversation and starts a new id while `RoutedSidebar` stays on `/`. `useChatMessages.streamReply` takes the optional guest history. `ChatView` shows a notice above the chat box ("Your chats won't be saved unless you sign in") with a Sign in button for guests, and no longer redirects to `/chats/[id]` for them. Clicking New notebook while signed out opens the new `SignInRequiredModal` (shadcn `Dialog`, "Notebooks are only available once you're signed in") instead of calling the database action and showing a toast; its Sign in link closes the dialog and the sidebar through `onSignIn`. Added a schema test for the history limits (52 tests total). Not done: guest conversations are lost on refresh, other signed-in features such as pinning and renaming are simply absent for guests, the rate limit is per server instance, and attachments are still not sent to the model.

- **Usage Limits:** Chat limits now live in Upstash Redis (`@upstash/ratelimit`, `@upstash/redis`) so counts are shared across server instances; `checkLimit` in `lib/rate-limit.ts` uses it when `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` are set (2 second timeout) and falls back to the in-memory limiter when they are missing or Redis errors. `lib/chat-limits.ts` holds the rules: a per-minute burst limit (10 guests, 20 signed in, keyed by the first `x-forwarded-for` address or user id) that still returns 429, a daily limit of model replies per person set by `CHAT_DAILY_LIMIT` (default 10, guests and signed-in users alike) and a global daily budget set by `GLOBAL_DAILY_MODEL_LIMIT` (default 500). `chooseReplySource` returns "model", "mock" (`USE_AI_MODEL=false`, not counted) or "limit"; once the daily or global limit is reached `/api/chat` streams `LIMIT_REPLY`, a sample reply, instead of an error, and saves it for signed-in users. Guests also get tighter input limits (2,000 characters, 10 earlier turns, 150 KB body), and the notice above the chat box changes to urge sign-in after 5 messages. Title generation shares the daily limit and stops when the global budget is spent. The dev mock reply no longer mentions `.env`. The client now removes the thinking placeholder and shows an error when a reply arrives empty, such as when the Gemini quota is exhausted, and the model is now `gemini-3.5-flash-lite` after `gemini-3.8-flash` hit its free daily quota. Added `lib/chat-limits.test.ts` and updated the title test (64 tests total). Notes: the limiter keeps a per-process cache of blocked callers until the window resets, so after manually clearing Redis counters the dev server must be restarted; the Upstash variables must be added on Vercel. Not done: when Gemini itself fails the user sees an error rather than the sample reply.
